# 🧠 What is OpenWrek?

OpenWrek is an **AI-native Web Design OS** built around the idea that
creating a great website should not require the user to manually coordinate
research, UX, visual design, motion, assets, development, testing, and
optimization.

Instead, OpenWrek coordinates these capabilities through an intelligent
system of:

- 🧠 **Second Brain**
- 🕸️ **Knowledge Graph**
- 🤖 **Specialized AI Agents**
- 🧩 **Design & Development Skills**
- 🔬 **Deep Research**
- 💾 **Persistent Memory**
- 🎨 **Creative Design Intelligence**
- ✨ **Motion & Interaction Systems**
- 🔌 **MCP / Tool Integration**
- 🌐 **Browser Execution**
- 🧪 **Visual & Technical QA**
- 🚀 **Build & Deployment Workflows**

The goal is not simply to generate code.

The goal is to create a system that can:

> **Understand → Research → Think → Design → Create → Build → Test → Improve → Remember**

🧪 Quality System

OpenWrek treats quality as evidence-driven execution.

Quality checks can include:

Area	Examples
Visual	Layout, spacing, hierarchy, visual consistency
Responsive	Desktop, tablet, mobile
Accessibility	Semantic structure, contrast, accessibility checks
Performance	Load behavior, asset efficiency
SEO	Metadata, structure, discoverability
Functional	Interactions, forms, persistence
Assets	Missing, broken, incorrect assets
Motion	Animation behavior and reduced-motion considerations

A task should not be considered successfully completed simply because
an AI model claims that it passed.

The system should require actual evidence from the relevant checks.

🎯 Design Philosophy

OpenWrek follows a few principles.

1. Intelligence before generation

Do not generate before understanding the project.

2. Research before imitation

Study references, extract patterns, then create original work.

3. Agents are specialists

A complex creative workflow should be decomposed into specialized capabilities.

4. Tools are capabilities

Agents should request capabilities rather than depend directly on vendors.

5. Memory compounds

Every useful project decision should have the potential to improve future context.

6. Evidence over claims

An agent should not claim that something works without appropriate evidence.

7. Human-directed autonomy

The system should automate execution while keeping important decisions
visible and controllable by the user.
